# Data model

## FHIR resource mapping

| Domain concept | FHIR resource | Notes |
|---|---|---|
| Patient | `Patient` | `address.state` drives licensure gating. Changing it is a clinical event. |
| Provider | `Practitioner` + `PractitionerRole` | Licensure per state lives on PractitionerRole |
| Availability | `Schedule` + `Slot` | Generated by the scheduling service; Medplum only stores |
| Booking | `Appointment` | `appointmentType` drives duration, modality, prep rules |
| Visit | `Encounter` | Links Appointment → Composition |
| Note | `Composition` | Sections: subjective, objective, assessment/plan |
| Weight, BP, waist, dose | `Observation` | **LOINC-coded, always.** Never free text |
| Check-in submission | `QuestionnaireResponse` + derived `Observation`s | |
| Lab order | `ServiceRequest` | |
| Lab result | `DiagnosticReport` + `Observation` | |
| Prescription | `MedicationRequest` | |
| Dispense / refill | `MedicationDispense` | Drives adherence + days-supply |
| Titration plan | `CarePlan` | References protocol definition id in `app` schema |
| Message | `Communication` | `category` = clinical / billing / scheduling / results |
| Task | `Task` | Owner, due, priority, business status |
| Consent | `Consent` | Versioned; store which version was signed |
| Coverage status | `Coverage` + `Account` | Mirrored from Stripe, never authoritative |

Custom observations (side-effect grade, adherence, hunger score) use a local
CodeSystem under the project namespace. Document every code in
`specs/codes.md` as you add it — undocumented local codes are how a lab data
model rots.

## Postgres `app` schema

```sql
-- Commercial
create table plan (
  id            uuid primary key,
  key           text unique not null,        -- essential | premium | concierge
  name          text not null,
  price_cents   int not null,
  stripe_price_id text not null,
  visits_per_month int,
  active        boolean not null default true,
  created_at    timestamptz not null default now()
);

-- Funnel: a lead is NOT a Patient until they pay
create table lead (
  id            uuid primary key,
  email         text,
  phone         text,
  state         text,
  bmi           numeric(4,1),
  conditions    text[],
  contraindications text[],
  prior_glp1    text,                        -- never | current | past
  eligibility   text,                        -- qualified | review | ineligible
  selected_plan text,
  utm           jsonb,
  stage         text not null,               -- quiz | plan | account | paid | abandoned
  patient_id    text,                        -- FHIR Patient id once converted
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);

-- Clinical protocol as data, not code
create table protocol (
  id            uuid primary key,
  drug          text not null,               -- tirzepatide | semaglutide | phentermine
  version       int not null,
  ladder        jsonb not null,              -- [{dose, unit, min_weeks, next}]
  hold_rules    jsonb not null,              -- {side_effect_grade, adherence_pct}
  max_dose      numeric,
  active        boolean not null default true,
  unique (drug, version)
);

-- Scheduling policy, editable without deploy
create table scheduling_rule (
  id            uuid primary key,
  appointment_type text not null,
  duration_min  int not null,
  modality      text not null,               -- video | in_person | async
  buffer_min    int not null default 0,
  min_lead_hours int not null default 2,
  cancel_window_hours int not null default 24,
  late_fee_cents int not null default 0,
  prep_requirements jsonb                    -- {labs_within_days, weight_logged}
);

-- Identity bridge
create table stripe_link (
  patient_id    text primary key,            -- FHIR Patient id
  stripe_customer_id text unique not null,
  subscription_id text,
  status        text not null,
  current_period_end timestamptz
);

-- Agent observability
create table agent_run (
  id            uuid primary key,
  agent         text not null,
  patient_id    text,
  input         jsonb,
  output        jsonb,
  tool_calls    jsonb,
  status        text not null,               -- drafted | approved | overridden | rejected
  reviewed_by   text,
  reviewed_at   timestamptz,
  created_at    timestamptz not null default now()
);

create table waitlist (
  id uuid primary key, email text not null, state text not null,
  created_at timestamptz not null default now()
);
```

> `agent_run` will contain PHI. It lives in the BAA-covered Postgres, never in a
> dev or logging environment outside coverage.

## Postgres `analytics` schema

dbt models, rebuilt nightly:

- `dim_patient` — demographics, tier, program stage, cohort month
- `fct_weight` — every weight observation, with days-since-start
- `fct_outcome` — %TBWL at 30/90/180/365 days per patient
- `fct_subscription` — MRR movement: new, expansion, contraction, churn
- `fct_funnel` — lead → qualified → plan → paid → booked → attended
- `fct_adherence` — refill gaps, missed doses, check-in completion
- `mart_cohort_outcomes` — %TBWL by tier × starting BMI × month
- `mart_retention` — survival curves by cohort

Every metric shown in the console's Insights view must resolve to one of these.
No ad-hoc SQL in the application layer.
